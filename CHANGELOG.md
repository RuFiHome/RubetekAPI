# Changelog

## Unreleased

### WebRTC и TURN (PR #10, включает PR #9)

- Ручная настройка `ice_servers` из PR #9 включена в PR #10: окончательная
  конфигурация передаётся при создании PeerConnection, пустой список имеет
  приоритет. Перенесены все четыре теста PR #9 с настоящими объектами aiortc,
  адаптированы к явной ошибке при EOF сигнализации. PR #9 закрыт как заменённый.
- `run()` восстанавливает соединения с экспоненциальной паузой 2–30 секунд
  и jitter. После стабильной связи 30 секунд задержка сбрасывается.
- Каждая попытка запрашивает свежий видеотокен; явно переданный используется
  только один раз. Provider разрешается до запроса короткоживущего токена.
- `close()` терминален и идемпотентен, останавливает token/provider/backoff;
  отмена ожидающего caller не отменяет общую задачу освобождения ресурсов.
- Готовность определяется по connected transport; ошибки WebSocket/keepalive,
  PeerConnection и offer timeout приводят к восстановлению. Ранние ICE
  буферизуются до remote description.
- `create_web_rtc_viewer()` и `watch_video()` передают ICE/provider/retry options.
  `watch_video()` сохраняет возврат незапущенного viewer; исправлена документация.
- Убрано диагностическое логирование всех полей клиента, включая секреты.

### Автоматический источник TURN

- Нативный клиент API создаёт один общий lazy `RuStoreTurnProvider`. После
  обычного входа viewer не требует ручной настройки. Явный ICE/provider или
  `auto_turn=False` переопределяет источник; false сохраняет прежний Google STUN.
- Публичный APK официального клиента `com.fsk.home` получается из RuStore,
  только по HTTPS с `static.rustore.ru`, без redirects и аккаунтных Rubetek
  токенов/cookies. Первый download около 200 МБ, ограничение APK 512 МиБ.
- Это статические SDK credentials из literal-return методов
  `CloudIotConstantProvider.provideCOTURN*`, а не найденный API выдачи временных
  TURN-токенов. APK никогда не устанавливается и его код не исполняется.
- Ограничены размеры APK/DEX и таблиц DEX, принимаются только известные
  literal-return методы. Ошибки не содержат возвращённых credentials.

### Проверка подписи APK

- Официальный Android `apksig 8.13.0` проверяет v2/v3 подпись и целостность
  APK. Python затем проверяет закреплённый SHA256 сертификата издателя,
  подписанное имя пакета и version code, соответствие версии метаданным
  и запрет отката относительно ранее проверенного APK.
- Сертификат закреплён в `apk_signature.py`; новые pins из APK/метаданных сети
  не принимаются. Смена ключа издателя требует проверенного обновления кода.
- Verifier JAR скачивается с точного URL официального Google Maven и сверяется
  по закреплённому SHA256 перед каждым запуском, включая диск-кэш. Неверная
  подпись или отсутствие verifier не отключают проверку.
- MIT Java bridge поставляется с исходником и воспроизводимым `.class`;
  CI пересобирает его JDK 21 с `--release 11 -g:none` и сравнивает результат.
  В extra `[webrtc]` добавлен `jdk4py` с готовой Java runtime; отдельная системная
  Java не нужна. Требуется платформа с поддерживаемым wheel jdk4py.
- APK помещается в отдельный staging-файл; проверяется и читается тот же файл.
  Локальный `apk_path` также проходит обязательную проверку. Альтернативный
  пакет требует явно заданных проверенных `trusted_certificates`.

### Кэш, обновления и закрытие

- Подписанный base APK кэшируется в `%LOCALAPPDATA%/saarubetek-api` на Windows
  или `~/.cache/saarubetek-api` на остальных платформах. После перезапуска его
  подпись проверяется заново. На POSIX новые каталоги 0700, файлы 0600;
  Windows использует ACL пользователя. Извлечённые credentials отдельно не
  сохраняются, но сам APK содержит SDK-константы: кэш нужно защищать.
- Фоновая задача проверяет версию каждые 24 часа независимо от новых viewer
  и обрывов видео. При прежней версии APK не скачивается повторно. Интервалы
  настраиваются `refresh_seconds` и `failure_retry_seconds`.
- Новая версия принимается только после полной проверки и используется
  следующими соединениями без прерывания текущего видео.
- Ошибки обновления сохраняют последнюю проверенную конфигурацию, отражаются
  в `last_update_error` и безопасном warning. Без доверенной конфигурации
  возвращается ошибка, без перехода на STUN. Cooldown сети 5 минут;
  подписи/версии — минимум основной интервал, по умолчанию сутки.
- `api.close()` закрывает viewer и update watcher. Отдельно созданный provider
  закрывается через собственный `close()`; завершение download после закрытия
  не может заново запустить watcher.

### Проверки и ограничения

- 39 unittest: lifecycle/cancellation/backoff, свежие токены, early ICE,
  factory defaults, extraction, cache/lock/cooldown, периодические проверки,
  close race, verify-before-extract, rollback. Реальная Android verifier на
  публичных AOSP fixtures проверяет верную/повреждённую подпись, изменение
  содержимого, чужой ключ, package/version и подмену verifier-кэша.
- Полная загрузка RuStore с проверкой подписи совпала с отдельно проверенными
  приватными рабочими TURN-настройками.
- Нативный factory без ICE/provider options дал по 5 декодированных кадров
  реальной камеры и домофона; api.close остановил viewer и watcher.
- Проверено видео четырёх камер и домофона; после принудительного WS-разрыва
  камеры/домофона получен новый токен и новые кадры, после close запросов нет.
- Проверены Python 3.12 на Windows и Ubuntu; CI matrix 3.10/3.12. Внешний workflow требует разрешения
  владельца upstream, пока не считается пройденным.
- `close()` может ждать штатные TURN deallocation retries aiortc. Readiness
  transport не гарантирует первый кадр: медиатреки читает on_track приложения.
- Формат SDK/API магазина может измениться и вызвать fail-closed.
- В репозитории нет vendor APK, рабочих TURN credentials или данных аккаунтов.
  Test APK — публичные AOSP fixtures с отдельной лицензией Apache-2.0.
